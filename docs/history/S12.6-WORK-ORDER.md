## 0. 阶段目标

在前面全部阶段通过后，由用户人工验证一次完整真实电源链路（睡眠 → 重启 → 关机），确认：

1. 真实动作准确执行**一次**，不重复、不补执行。
2. 取消与延迟在真实电源模式下有效，不会误执行。
3. 提醒窗口、倒计时、确认流程在真实模式下正常。
4. 崩溃/异常退出后状态正确恢复，已中断任务**不会**补执行真实电源。
5. 日志可追溯每一次真实动作。
6. 验收结束后真实电源开关恢复为关闭（除非用户明确决定长期启用）。

**安全前提：本阶段会真实地让电脑睡眠、重启、关机。** 执行前必须完成备份与数据保护，逐项确认后方可开始。

6. 日志目录 `%LocalAppData%\AutoShutdown\logs` 及 `autoshutdown-YYYY-MM-DD.log` 轮转规则。
7. 确认当前运行的 EXE 是**最新** Release 构建（含 S12.5），不是旧版缓存。

## 3. 开启真实电源模式（双闸门闸门一）

真实电源验收需要 `TestMode=false` 且 `RealPowerEnabled=true`。

### 3.1 配置修改方式（二选一，推荐 UI）

1. 首选：在软件"软件设置"页提供真实电源模式开关（S12.5 已实现的话）；关闭"安全测试模式"时，界面必须要求用户对"启用真实电源"进行明确二次确认。
2. 兜底：手动编辑 `%LocalAppData%\AutoShutdown\config.json`，设置 `"TestMode": false, "RealPowerEnabled": true`；修改后重启软件，确认配置状态显示真实电源模式，且创建任务按钮可用。

### 3.2 开启后确认

- [ ] 顶部/创建区域显示"真实电源模式"标识（而非"安全测试模式"）。
- [ ] 创建真实任务前，界面弹出明确二次确认（闸门二）且文案完整（说明将真实执行、需保存工作）。
- [ ] 取消该确认时：零写入、零任务创建。

## 4. 人工验收顺序（严格按此顺序，逐步推进）

### 4.1 第一步：安全模式下的取消与延迟回归（不开启真实电源）

在进入真实电源前，先用**安全测试模式**验证操作逻辑仍正确：

- [ ] 创建 10–30 秒短倒计时任务。
- [ ] 任务进入"等待执行"后，"延迟10分钟"与"取消任务"可用。
- [ ] 点"延迟10分钟"：下次执行时间 +10 分钟。
- [ ] 点"取消任务"：二次确认 → 任务取消 → "创建任务"恢复可用。
- [ ] 全程确认无真实关机/重启/睡眠/休眠。

**此步证明：真实模式的基础操作链路（创建/延迟/取消/确认）与安全模式一致，降低真实验收误触风险。**

### 4.2 第二步：真实模式下的取消与延迟验证

开启真实电源模式（§3）后，**先不真正执行**，验证"不会误执行"：

- [ ] 创建一个较长时间的真实任务（如 2–3 分钟），触发确认对话框并确认。
- [ ] 在倒计时中途点"取消任务"：任务取消，**不得**触发真实电源。
- [ ] 再创建一个真实任务，在提醒窗口出现后点"延迟10分钟"：执行时间延后，**不得**触发真实电源。
- [ ] 确认提醒窗口文案正确（显示真实动作名称与倒计时）。

**通过标准：真实模式下取消与延迟有效，任何被取消/延迟的任务均零真实调用。**

### 4.3 第三步：提醒窗口与短倒计时冒烟（真实模式，但不触发动作）

- [ ] 创建短倒计时（如 10–15 秒）真实任务并确认。
- [ ] 在提醒窗口出现后，点"取消"：任务取消，不触发电源。
- [ ] 重复一次，在提醒窗口点"延迟"：任务延后，不触发电源。

**此步验证提醒窗口在真实模式下正常显示与交互，仍不执行真实电源。**

### 4.4 第四步：真实睡眠（优先测风险最低的睡眠）

- [ ] 关闭重要程序，再次确认已保存。
- [ ] 创建"睡眠"真实任务（短倒计时 + 确认）。
- [ ] 观察：倒计时到点后电脑进入**睡眠**状态。
- [ ] 唤醒电脑，确认成功唤醒，软件进程仍在运行（或自动恢复）。

**通过标准：睡眠准确执行一次，唤醒后应用/状态正常。**

### 4.5 第五步：真实重启

- [ ] 保存所有工作，关闭重要程序。
- [ ] 创建"重启"真实任务（短倒计时 + 确认）。
- [ ] 观察电脑执行**重启**。
- [ ] 重启完成后登录，启动软件，检查：
  - [ ] 日志中记录 `RealPowerSucceeded`（或对应事件）；
  - [ ] 状态恢复正确（无遗留 Executing 任务被补执行）；
  - [ ] 托盘图标正常、主窗口可打开；
  - [ ] 开机自启动状态符合预期（若之前未启用，则不会自动启动）。

**通过标准：重启准确执行一次；重启后状态正确、无补执行。**

### 4.6 第六步：真实关机（最后测风险最高的关机）

- [ ] 保存所有工作，关闭重要程序。
- [ ] 创建"关机"真实任务（短倒计时 + 确认）。
- [ ] 观察电脑执行**关机**。
- [ ] 重新开机，启动软件，检查：
  - [ ] 日志记录 `RealPowerSucceeded`；
  - [ ] 无补执行（关机前任务不应在开机后再次触发）；
  - [ ] 应用启动正常。

**通过标准：关机准确执行一次；开机后无补执行、日志可追溯。**

### 4.7 第七步：执行一次性与不重复验证

- [ ] 每类真实动作（睡眠/重启/关机）只执行一次，无重复触发。
- [ ] 日志中每类动作的 `RealPowerSucceeded` 记录次数为 1。
- [ ] 无"到点后又补一次"现象。

### 4.8 第八步：崩溃恢复不补执行验证

利用现有 `SchedulerEngine.TryRestoreAsync` 机制（恢复时把 Warning/Executing 任务标记为 `Interrupted`）：

- [ ] 创建一个真实短倒计时任务并确认。
- [ ] 在倒计时结束前（仍处于 Warning/Executing），通过任务管理器**强制结束** `AutoShutdown.App.exe` 进程（模拟崩溃）。
- [ ] 重新启动软件。
- [ ] 确认：
  - [ ] 恢复后的任务状态为"已中断"（Interrupted）而非继续执行；
  - [ ] **没有**触发真实关机/重启/睡眠/休眠；
  - [ ] UI 显示中断状态，可"清除"该记录；
  - [ ] 日志记录中断原因。

**通过标准：崩溃恢复后已中断任务绝不补执行真实电源。**

## 8. 立即停止条件

出现任一情况立即停止，不得继续下一类真实动作：

1. 取消/延迟在真实模式下无效或误触发电源。
2. 提醒窗口未显示、倒计时异常或确认流程被跳过。
3. 同一任务触发多次电源，或恢复后被补执行。
4. 真实电源执行后应用无法启动、状态文件损坏。
5. 日志缺失、无法追溯真实动作。
6. 任何一步出现非预期关机/重启/睡眠。
7. 无法恢复为安全测试模式。

停止后记录证据（日志、截图、现象），等待 GPT 审查与用户确认。
