## 5. 集成缺陷（L4 冒烟暴露，检查点 6 处置）

### 5.1 现象
启动候选 EXE 后，日志停在「调度引擎启动中」（`SchedulerStarting`）不再前进，进程存活但永不进入 `SchedulerRunning`。

### 5.2 根因（async-over-sync 死锁）
`ApplicationLifetimeCoordinator.RecoverFromCrash()` 在 WPF UI 线程上执行
`_crashRecoveryManager.RecoverAsync(...).GetAwaiter().GetResult()`，而 `RuntimeStateStore.LoadAsync`/`FileStorage.ReadAsync`
内部的 `await JsonSerializer.DeserializeAsync(...)` 未使用 `ConfigureAwait(false)`：async I/O 异步完成后，continuation
被投递回已阻塞的 UI 调度器 → 永久挂起。

### 5.3 修复（提交 `4289bc1`）
1. `FileStorage.cs`：全部存储 await 增加 `ConfigureAwait(false)`。
2. `RuntimeStateStore.cs`：`LoadAsync` 的 `ReadAsync<JsonElement>` await 增加 `ConfigureAwait(false)`。
3. `ApplicationLifetimeCoordinator.RecoverFromCrash`：恢复工作移到后台线程执行（`Task.Run(...).GetResult()`），
   线程池线程无 SynchronizationContext，杜绝该类死锁，同时保留「恢复完成后才启动调度」的同步顺序保证。

### 5.4 回归测试（新增 1 项）
`S13_L4_StartupDeadlockRegressionTests.cs`：在「Post/Send 即抛错的 SynchronizationContext」下对
`RuntimeStateStore.LoadAsync(...).GetResult()` 做阻塞读取；若任一 await 捕获上下文会立即抛错/中止。
已验证：去掉修复后该测试中止运行（红），恢复后通过（绿）。
