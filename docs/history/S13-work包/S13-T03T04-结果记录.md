## 2. V2 状态模型与 V1→V2 映射

### 2.1 `RuntimeState`（多实例）

| 字段 | 类型 | 说明 |
|------|------|------|
| `SchemaVersion` | `int` | 当前 = 2；必须存在且为整数；>2 判 `UnsupportedVersion`；<2 且非 V1 单实例无迁移链判 `Invalid` |
| `Instances` | `IReadOnlyDictionary<Guid, TaskInstance>` | 键 = `SourceTaskId`（task id）；可为空字典但不得为 null |
| `LastUpdatedAt` | `DateTimeOffset` | 快照更新时间 |

- 删除 `CurrentInstance`（V1 单实例字段）。V1 单实例迁移经 GATE-Q3（见 §4），不进入 V2 模型。
- 每实例字段：`InstanceId` / `SourceTaskId` / `ActionSnapshot` / `State` / `ScheduledFireTime` / `WarningStartTime` / `StageToken` / `HasExecuted` / `CreatedAt` / `RealPowerConfirmed` / `RealPowerConfirmationId`（类型名 `TaskInstance` 不变，故 `IScheduledTaskHandler`/`IShutdownWorkflow` 签名不变，仅内部枚举引用切换）。

### 2.2 V1 `TaskState` → V2 `TaskInstanceState`

| V1 | V2 |
|----|----|
| Idle / Scheduled | `Waiting` |
| Warning | `Confirming` |
| Executing | `Executing` |
| Completed | `Executed` |
| Failed | `Faulted` |
| Cancelled | `Cancelled` |
| Interrupted | `Interrupted` |

- V2 新增 `Running`（Pre-Pipeline 暂态）。本次 deadline 触发后走 `Waiting→Running→Confirming`（`Running` 为即刻瞬态，无真实管线），全部经 V2 冻结状态机白名单。真实 Pre-Pipeline 归 S16。

## 3. SchedulerEngine 多任务接线

- 构造函数 8 参：`(IStorage, IClock, ISchedulerDeadlineSource, ITaskService, ITaskInstanceStateMachine, IIdentifierGenerator, IScheduledTaskHandler, ITaskArbitrator)`。
- `SchedulerSnapshot`：单 `CurrentInstance` → 多实例 `Instances` 集合 + `EngineStatus` + `LastUpdatedAt`。
- 命令定位：Snooze/Cancel 按 `InstanceId` + `StageToken` 定位实例；错误身份 → `NoCurrentTask`，过期令牌 → `StaleCommand`。
- V2 语义：Snooze 仅 `Waiting`；Cancel 允许 `Waiting`/`Confirming`；`ClearTerminal` 移除终态实例（V2 无 Idle 态）。
- **仲裁调用点**：同刻多实例到期时调用 `ITaskArbitrator.Arbitrate(dueInstances, now)`；无自动赢家（`RequiresUserDecision=true`）时引擎安全失败（fault），不擅自二选一。生产注册 `NoOpTaskArbitrator` 过渡（正式实现与 DI 注册归 T06）。
- **StageToken 刷新**：`Executed→Waiting`（Reschedule）时经 `IIdentifierGenerator` 刷新 `StageToken`。
- **非法转换审计**：非法状态转换记 `Error` 级审计日志（经 `IApplicationLogger`，新增 `LoggingTaskInstanceStateMachineDecorator`）。

### 仲裁契约（T04 定义 + 消费，T06 实现）

`TaskArbitrationResult`：`WinnerTaskId` / `MergedTaskIds` / `RescheduledTaskIds` / `RequiresUserDecision` / `DecisionReason`。

## 4. GATE-Q3：旧 V1 runtime.json 备份后重建

| 触发 | 行为 |
|------|------|
| `SchemaVersion=1` 且单实例结构（`CurrentInstance`） | 备份 `runtime.json → runtime.json.v1bak`，然后重建空 V2 多实例态；结果状态 `Migrated`，`BackupPath` 指向 `.v1bak` |
| 备份失败 | 不覆盖原文件、不重建，原样保留 |
| 文件损坏 | `Corrupt`（不伪造空态回退） |
| 未知版本（>2） | `UnsupportedVersion` |
| 文件不存在 | `NotFound`（不伪造空态） |
| V1 结构但非单实例（既无 CurrentInstance 又 version<2） | `Invalid`（无迁移链，拒绝） |

- 旧 V1 单实例被原样备份，**未伪造 task id、未残留单实例**；新 runtime.json 为 `SchemaVersion=2` 空 `Instances`。

## 6. 测试证据

### 6.1 新增 `RuntimeStateStoreTests`（15 项）

### 6.2 `SchedulerEngineTests`（多任务语义）

关键用例：

- `ClearTerminal_ValidClearsInstance` —— 移除终态实例（V2 无 Idle 态）。
- `SnoozeAndCancel_WithWrongIdentityOrToken_ReturnStaleWithoutWrites` —— 错误身份 → `NoCurrentTask`、过期令牌 → `StaleCommand`。
- `Run_WhenRecoveredScheduledIsInFuture_EstablishesWait`、`Run_RecoversWarningAndExecutingToInterrupted_WithoutHandler` —— 崩溃恢复：`Running`/`Confirming`/`Executing → Interrupted`（`CrashRecovered`），不调 handler。
- `Run_WhenRuntimeStateIsInvalid_Faults` —— V2 非法运行态（null Instances / 空 InstanceId / 结构错）判故障。

### 6.3 `CorePipelineIntegrationTests`（端到端）

- `F_RecoverExecuting_Interrupted_NoExecution`、`F_RecoverWarning_Interrupted_NoExecution`、`RecoveredInstances_NeverInvokeWorkflowOrPower` —— 恢复实例绝不触发 workflow/power。
- `C_SnoozeFromWaiting_OldDeadlinesZero_NewFireOnce` —— Waiting 态 snooze 语义。
- 持久化断言改写为多实例：`s.Instances.Values.Any(i => i.State == Executing && i.HasExecuted)`。

### 6.4 V2 状态机（`TaskInstanceStateMachineTests`）

15 边白名单；恢复边 `Running`/`Confirming`/`Executing → Interrupted`（`CrashRecovered`）已在状态机层确认合法；`Waiting` 无 interrupt 边（非瞬态）。

> 仲裁「同时到期」调用点当前经 `NoOpTaskArbitrator` 覆盖单到期（赢家 = 该实例）与多到期（`RequiresUserDecision=true` → 引擎 fault）两条路径；正式 Fake 仲裁注入的决策分支回归归 T06。
