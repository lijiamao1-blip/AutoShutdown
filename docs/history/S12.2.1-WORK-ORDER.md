在 S12.3 之前提供两个简单入口：一个重新构建后启动最新 UI，一个直接打开最近一次成功构建的 UI，便于用户及 WorkBuddy 中其他模型进行前台视觉微调。

### 0.2 硬边界

1. 只允许在 `tools` 目录新增启动脚本和说明。
2. 不修改 Core、App 生产功能、测试代码、注册表或真实电源逻辑。
3. 不设置开机自启，不请求管理员权限，不结束任何进程。
4. 不删除 `bin`、`obj`，不运行测试，不寻找其他目录中的旧 EXE。
5. 软件继续使用 `FakePowerService` 安全测试模式。
6. 本预览入口仅属于开发环境，不进入正式发布目录。

## 3. “启动UI预览”入口行为

1. 切换到项目根目录。
2. 按规则找到可用 .NET SDK。
3. 执行 Release 构建。
4. 构建失败时：显示“构建失败，未启动软件”，保留构建错误，等待用户确认后退出；**不得启动旧 EXE**。
5. 构建成功后检查：

   `src\AutoShutdown.App\bin\Release\net8.0-windows\AutoShutdown.App.exe`

6. EXE 存在时使用 `Start-Process` 启动并立即结束脚本，不长期占用命令窗口。
7. 应用自身的单实例与 Named Pipe 规则继续生效；已有实例时仅唤起原窗口。

---

## 4. “仅打开现有UI”入口行为

1. 不执行构建。
2. 只检查固定 Release EXE 路径。
3. EXE 存在时直接启动。
4. EXE 不存在时显示：尚未找到可运行的 UI，请先运行“启动UI预览.cmd”完成构建。
5. 不搜索其他目录，不误开旧版本。
