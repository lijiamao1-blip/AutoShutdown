# AutoShutdown V2 — S21 阶段结果记录（Wake-on-LAN 与一次性 RTC 唤醒）

## 阶段结论

**通过（两机 Magic Packet 与一次性 RTC 真实设置/唤醒、真实桌面 GUI 冒烟待人工复核）。**

S21 实现两大目标：① 向用户显式配置的局域网目标发送 Magic Packet 唤醒他机（严格 MAC 校验、稳定 id/名称/MAC/可选 IPv4 广播/端口配置、原子写入 + 备份证据、加载区分 NotFound/Corrupt/Invalid/UnsupportedVersion、包 = 6 字节 0xFF + MAC×16、只向用户配置目标发送、绝不扫描/自动发现/访问公网、socket 失败结构化上报）；② 关机前可设置一次性 RTC 唤醒本机（平台无关能力/设置/清除抽象、能力诚实声明「仅睡眠/休眠可唤醒、完全关机 S5 不可唤醒」、权限不足/固件拒绝/取消/清理失败一律明确失败绝不伪装成功、无驱动安装/固件改写/电源策略更改、RTC 仅作为受控关机前步骤、不实现独立定时唤醒）。

## 检查点执行

### C1 Magic Packet 与目标管理（提交 `ad2de39`）

`MagicPacket`：102 字节 = 6 字节 `0xFF` + 目标 MAC 重复 16 次，精确字节级验证；`MacAddress` 严格解析（冒号/短横/点分四组/无分隔，大小写不敏感，规范输出大写 `AA:BB:CC:DD:EE:FF`，任何混合分隔/非十六进制/字节数错误一律拒绝）；`TargetMachineStore`（`target-machines.json`，复用 `IStorage` 原子写入 + 备份证据，加载区分 NotFound/Corrupt/Invalid/UnsupportedVersion/IoFailure）；`TargetMachineManager` 增删改（损坏文档拒绝写入、绝不静默覆盖证据）；`WakeOnLanService` 经 `IUdpDatagramSender` 抽象发送（UDP 可测试替身，自动化绝不发真实 UDP）；socket/目标缺失/非法一律结构化失败。

### C2 一次性 RTC 唤醒（提交 `c007a7e`）

`IRtcWakeService` 平台无关抽象：`GetCapabilityAsync`（诚实声明唤醒范围：Windows waitable timer 可唤醒睡眠 S3/休眠 S4，不可唤醒完全关机 S5）/ `SetWakeAsync`（不支持/权限不足/固件拒绝/取消一律明确失败）/ `ClearAsync`（清除失败明确上报 CleanupFailed）。真实实现 `Win32RtcWakeService` + `Win32RtcWakeNativeApi`（CreateWaitableTimerExW + SetWaitableTimer fResume=TRUE），P/Invoke 全部收敛于 `Win32PowerNativeApi.cs`（冻结契约：DllImport 只允许存在于该文件，本阶段经源码契约断言）。`RtcWakeAction` 作为受控关机前步骤挂载 Pre-Pipeline（追加于 CloseApps 之后，冻结顺序不变）；`ShutdownWorkflow` 在电源未被接受时尽力清除已武装唤醒（安全网，清除失败明确上报，绝不残留游离定时器）。

### C3 调度/Workflow 集成（提交 `73cdf0d`）

WoL 作为显式任务类型：`PowerAction.WakeOnLan = 5`；`TaskDefinition`/`TaskInstance` 携带 `TargetMachineId`（+ `RtcWakeTimeUtc`，均 nullable，无 schema 版本提升）；`TaskDefinitionValidator` 规则（WoL 必须非空 TargetMachineId、禁止 RtcWakeTimeUtc；电源动作禁止 TargetMachineId）；`WakeOnLanTaskExecutor` 校验动作/目标后经 `IWakeOnLanService` 发送，失败抛 `ScheduledTaskHandlingException` → 实例 Faulted（绝不伪造成功）；`ShutdownScheduledTaskHandler` 按动作分派（WoL → 执行器，其余 → ShutdownWorkflow），**不改 SchedulerEngine/TaskArbitrator**（默认 StrengthOf 0，仲裁与唯一电源出口不变）；RTC 唤醒时间经 PrePipelineContext 注入 Pre-Pipeline，仅作为关机前受控步骤。

### C4 UI·审计·候选（提交 `30f9daa`）

设置页新增两个分区：**Wake-on-LAN 目标机器**（名称/MAC/可选广播/端口输入 + MAC 格式提示「AA:BB:CC:DD:EE:FF（必填，大写十六进制）…默认向 255.255.255.255:9 发送」+ 目标列表 + 逐目标「测试发送/移除」，增删改立即原子持久化，损坏配置 fail-closed 阻止变更，测试发送结果明确显示成功/失败原因，默认清单为空绝不自动发送）；**一次性 RTC 唤醒能力**（能力探测只读展示：支持（区分仅睡眠/休眠 vs 含完全关机）/不支持/状态未知 fail-closed/查询失败，均明确显示原因，绝不设置任何真实唤醒定时器）。任务创建新增第 5 个动作「唤醒他机」+ 目标机器选择器：WoL 任务不经双闸门（不调用人工确认、RealPowerConfirmed=false、无人值守选项隐藏）、必须显式选择目标、不支持空闲触发、携带 TargetMachineId。组合根解析冒烟：完整 DI 图可解析 `MainWindowViewModel` 与两个新分区（`S21_CompositionRootResolvesTests`）。

### D1 最小返修：WoL 网络边界 fail-closed（提交 `94af71b`）

针对 C4 验收复核发现的网络边界缺口做最小返修，范围严格限于 WoL 发送目的地合法性，未进入 S22/S23、未处理 S19 D2B/D2C、未改 RunCommands 默认空白名单。

- **新边界（`WakeOnLanBroadcastPolicy`，纯函数 + 可注入本机接口来源）**：仅两类目的地允许发送 —— ① 默认有限广播 `255.255.255.255`（恒允许）；② 本机**当前活动** IPv4 接口对应子网的**定向广播**地址（如 `192.168.1.100/24` → `192.168.1.255`）。
- **其余一律结构化拒绝并输出可诊断原因**：公网单播（RFC1918 之外）、组播（224-239）、回环（127.x）、链路本地（169.254.x）、`0.0.0.0`、IPv6、以及任意非本机接口网段的地址（如其它子网广播 `10.0.0.255`）。拒绝时**绝不调用 UDP sender**（测试断言 sender 调用数为 0）。
- **单一共享拒绝点**：边界只在 `WakeOnLanService.SendAsync` 内强制。UI「测试发送」（`WolTargetsSectionViewModel.TestSendTargetCommand`）与调度 WoL 任务（`WakeOnLanTaskExecutor`）都经此发送路径，天然复用同一边界；不改调度/仲裁/状态机/RTC/Pre-Pipeline/唯一 IPowerService 出口。
- **配置载入兼容**：store 加载逻辑零改动，含旧不安全广播地址的配置仍 `Success` 载入并完整保留（供展示/人工修正）；安全拒绝只发生在发送时刻（fail-closed）。
- **真实接口来源（`LocalNetworkInterfaces`）**：仅用托管 `System.Net.NetworkInformation` 枚举本机活动接口（无 P/Invoke、无扫描、无自动发现、无公网访问）；枚举失败返回空清单 → 仅有限广播可用（fail-closed）。
- **DI**：注册 `IWakeOnLanLocalNetworks`/`WakeOnLanBroadcastPolicy`；`WakeOnLanService` 构造注入边界。
