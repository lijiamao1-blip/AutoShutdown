## 返修内容

### 修复 1 — 倒计时边界确认裁决（`SchedulerEngine`）

`EnterExecutingAsync` 在 `HasExecuted` 守卫之后、`Confirming→Running` 之前调用 `ResolveCountdownConfirmationAsync`：

- 重新读取最新实例（`FindInstance`），实例非 Waiting/Confirming 一律拒绝（终态胜出）；
- Confirming 且 `IsIdleTriggered` 时在到期边界重新检测输入，恢复即 `CancelIdleTriggeredAsync`（输入恢复胜出）；
- 仅对 `UseUnattended=true` 的任务评估无人值守：策略服务/评估器缺失、授权异常或评估不 `AllowsPower` 一律 `CancelUnattendedAsync`（fail-closed）；
- `OperationCanceledException` 原样上抛，其余异常按取消终结。

裁决结果为 false 即取消/终结，不进入 `_handler.HandleDueAsync`，因此 Pipeline 与电源调用均为 0。

### 修复 2 — 任务级「使用无人值守」选择（`MainWindowViewModel` + `MainWindow.xaml`）

`TaskDefinition`/`TaskInstance` 新增 `UseUnattended`（默认 false），`TaskService.Create` 在两条实例构造路径均拷贝该标志。UI 侧：

- `IsUnattendedTaskOptionVisible`：仅真实电源模式显示；
- `IsUnattendedTaskOptionAvailable`：真实电源模式 + 本地无人值守授权有效且与所选动作匹配；
- `TryBuildDefinition`：真实电源模式下，选中 `UseUnattended` 且可选时创建 `RealPowerConfirmed=false + UseUnattended=true`；未选中走原人工确认路径 `RealPowerConfirmed=true`；选中但不可选时直接报错拒绝；
- `ShutdownWorkflow.ResolveRealPowerConfirmationAsync` 增加 `UseUnattended` 闸门：未显式选择且无人工确认即拒绝，全局授权不会自动套用。

## 关键安全不变量核对

- **取消/用户活动在到期边界优先**：`ResolveCountdownConfirmationAsync` 先读最新实例终态、再检测输入恢复，均先于 `Confirming→Running`，Pipeline 与电源调用为 0。
- **无人值守不默认跳过人工确认**：`UseUnattended` 默认 false；未显式选择即 `RealPowerConfirmationMissing` 拒绝（`ShutdownWorkflow` 双闸门之二闸门）。
- **全局授权不自动套用到所有任务**：仅 `UseUnattended=true` 才评估无人值守；UI 侧仅在授权有效且动作匹配时可选中。
- **授权异常/失效/动作不匹配一律 fail-closed**：引擎边界 `CancelUnattendedAsync` 取消 + 电源=0；UI 侧 `RefreshUnattendedTaskAvailabilityAsync` 异常即不可选。
- **不改冻结状态机/双闸门/唯一电源出口/Pre-Pipeline 顺序**：仅新增倒计时边界裁决与任务级显式选择，`Confirming → Running → OfficeSave → RunCommands → CloseApps → 唯一电源调用` 链路不变。
- **无真实关机/重启/睡眠/休眠/关闭真实用户应用**：全程 Fake/Guarded PowerService + RecordingPowerService 替身；S19 限制继续有效（RunCommands 本地白名单默认空，D2B/D2C 未处理）。
