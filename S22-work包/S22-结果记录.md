**通过（真机任务可见/更新/删除/冗余触发/权限失败与卸载清理待人工复核）。**

S22 实现「以本地 TaskCollection 为唯一事实源，把任务单向（outbound）同步到 Windows 任务计划
程序」：创建、更新、删除与冗余触发，绝不 inbound、绝不双向。外部任务全部放入专属目录

## 检查点执行

### CP1 依赖与映射（提交 `57f1fc4`）

- **依赖决策**：`Microsoft.Win32.TaskScheduler` 2.12.2（dahall，MIT，纯托管）。API 逐一验证：
  `TaskService.Connect()/GetFolder(path)/RootFolder.NewTask()`、`TaskFolder.RegisterTaskDefinition`
  （含 `TaskCreation`/`userId`/`password`/`TaskLogonType`/`sddl`）、`DeleteTask(name, bool)`、
  `Tasks`、`CreateFolder(path, sddl, bool)`；`Task.Name/Enabled/LastRunTime/Definition.Path`；
  `TaskDefinition.Triggers/Actions/Settings/RegistrationInfo`；
  `TaskSettings.Enabled/StartWhenAvailable/ExecutionTimeLimit/IdleSettings.IdleDuration`；
  `DailyTrigger(Int16)/TimeTrigger(DateTime)/WeeklyTrigger(DaysOfTheWeek, Int16)/
  MonthlyDOWTrigger(DaysOfTheWeek, MonthsOfTheYear, WhichWeek)/IdleTrigger()`；
  `ExecAction(path, args, workingDir)`；`DaysOfTheWeek` 位标志、`WhichWeek`、`MonthsOfTheYear`；
  `TaskCreation.CreateOrUpdate`、`TaskLogonType.InteractiveToken`、`Trigger.StartBoundary`。
- **映射冻结（`TaskSchedulerMapper`）**：本地 `TaskDefinition` → 平台无关 `ExternalTaskSpec`
  （稳定外部任务名 = `TaskSyncNaming.BuildTaskName(id)`、字段、触发、禁用、时区）。
  专用目录 `AutoShutdown V2`（`TaskSyncNaming.DedicatedFolderPath`）、应用标识 `AutoShutdownV2`
  （`AppIdentifier`）、分隔符 `::`、解析回验 `BuildTaskName`→`TryParseOwnedTaskName`（构建后回验
  fail-closed）。时区统一走 `IClock.LocalTimeZone`（不可注入本机时区差异）。

### CP2 Adapter 与同步服务（提交 `5549778`）

- **`ITaskSchedulerAdapter`**：`QueryOwnedAsync`（只解析自家任务名，其余跳过）/
  `CreateAsync`/`UpdateAsync`（CreateOrUpdate 幂等）/`DeleteAsync`（删除前二次校验自家名）。
- **`TaskSyncService`**：读本地 `GetAll()` → `TaskSchedulerMapper` 映射期望 → 查询外部 →
  幂等比较（`TaskSyncEquivalence`：name+enabled+触发签名+动作）→ 创建缺失/更新失配/删除陈旧
  （仅自家）→ 逐任务部分失败报告（`TaskSyncReport`：Created/Updated/Deleted/Unchanged/Failed/
  SkippedForeign）。绝不写本地、绝不 inbound、绝不修改传入快照；同一输入重复同步除 Unchanged
  外无任何变更（幂等，CP2 测试验证）。

### CP3 事件接入（提交 `342cdcd`）

- **`TaskCollection` 事件**：新增/更新/删除/分别启停各触发 `CollectionChanged`
  （`TaskCollectionChangedEventArgs`，含 kind + taskId）。
- **`TaskService` 转发**：`TaskCollection.CollectionChanged` 汇总后按 `ITaskService` 对外抛出
  （`ITaskService` 新增 `event EventHandler<TaskCollectionChangedEventArgs>? CollectionChanged`）。
- **`TaskSyncCoordinator`**：ctor 订阅事件，800ms 防抖合并；`SemaphoreSlim(1,1)` 单飞；
  `SyncNowAsync` 手动触发 + `SyncCompleted` 事件；`Dispose` 解绑。防回环：同步只读本地
  （GetAll）并只写外部，外部触发永不反向写本地事实源。

### CP4 UI·真机·清理（提交 `d4d183c`）

- **`WinTaskSchedulerAdapter`**（真机实现）：每操作 `using` 作用域 `TaskService`；`GetOrCreateFolder`
  专属目录；`BuildDefinition`（`StartWhenAvailable=true`、`ExecutionTimeLimit=Zero`、
  `ExecAction(AppExePath, "--trigger-task <id>", null)`——只回调本地应用，绝不携带电源命令；
  Idle 设置 `IdleSettings.IdleDuration`）；`BuildTrigger`（Time/Daily/Weekly/MonthlyDOW/Idle）与
  `MapObservedTrigger` 反向映射，保证外部任务签名可幂等比较（周期触发不含绝对开始日期，
  避免每日假更新）；权限/COM/IO 异常映射 `PermissionDenied/Invalid/IoFailure`；防御性二次校验
  非自家任务名一律 `Invalid` 拒绝。
- **外部触发回调（`ExternalTaskTriggerService` + `ExternalTriggerScheduleGate`）**：外部任务动作
  永远只 `--trigger-task <id>` 回调本地应用；主实例 headless 路径把触发交回本地唯一调度/Workflow
  （`ExternalTaskTriggerService.HandleExternalTriggerAsync`：读取 tasks.json 严格区分
  NotFound/Corrupt/Invalid/UnsupportedVersion，任何失败 fail-closed → 绝不执行电源；id 缺失/已删
  除/已禁用/时间闸门拒绝 → 不执行；构造 Executing 实例交给 `IScheduledTaskHandler` →
  WakeOnLan 执行器或 ShutdownWorkflow，ShutdownWorkflow 仍为唯一调用 IPowerService 的模块）。
  时间闸门以本地调度器算出期望触发窗口，±5 分钟容差裁决外部触发（补偿映射近似形态；
  Idle 触发本身即空闲证据）。
- **单实例 + 管道**：副实例把 `TRIGGER <id>` 经命名管道转发给主实例（`TryTriggerAsync`）；
  主实例无界面处理 `--trigger-task` 后退出，绝不经副实例执行电源。
- **设置页同步分区（`TaskSyncSectionViewModel` + MainWindow.xaml 卡片）**：启用/关闭开关、
  状态（新增/更新/删除/未变/跳过非本应用）、上次同步、错误与权限修复建议（以管理员身份运行）；
  启用 = 先持久化再立即同步；关闭 = 先清理全部自家外部任务再持久化，任一失败回滚开关
  （fail-closed，绝不出现「显示已关闭但外部任务仍触发」漂移）。
- **DI 接线**：`TaskSyncSettingsStore`、`ITaskSchedulerAdapter→WinTaskSchedulerAdapter`、
  `TaskSchedulerMapper`、`TaskSyncService`、`TaskSyncCoordinator`（`Environment.ProcessPath`）、
  `ExternalTriggerScheduleGate`、`TasksDocumentStore`（独立单例，供触发服务严格读事实源）、
  `ExternalTaskTriggerService`、`TaskSyncSectionViewModel`；`ApplicationLifetimeCoordinator`
  构造注入协调器（在调度引擎加载任务前解析，保证订阅不遗漏初始加载）；App 退出改为异步释放
  （`ActivationPipeServer` 只实现 IAsyncDisposable，原同步 `Dispose()` 会中断后续单例清理）。
- **卸载清理清单（交付 S-PKG）**：`S22-卸载清理清单.md` —— 三重条件（专属目录 `AutoShutdown V2`
  + 应用标识 `AutoShutdownV2` + 稳定本地 id `D` 格式 Guid）过滤后逐任务删除，目录空则删除目录，
  非自家任务绝不动；同事务先清外部任务再移除 tasks.json；审计日志；自检验证清单。
- **真机人工步骤**：`S22-真机人工步骤.md`（任务可见/更新/删除/冗余触发/权限失败/卸载清理），
  全部标记「未执行/人工待验」。

### CP4-D1 最小返修：同步门（提交 `660fb1d`）

自查发现「关闭同步 = 外部无本应用任务，绝不残留」不变量存在竞态：关闭后任何本地变更触发的
防抖同步会把已清理的外部任务**带回来**。最小返修：

- **`TaskSyncCoordinator.Enabled`（默认 true，向后兼容）**：`SyncNowAsync` 与每条防抖同步在门
  关闭时整体跳过——不触碰外部、不触发 `SyncCompleted`（避免 UI 闪动）。
- **DI 启动即按存储恢复门**（fail-closed：task-sync.json 缺失/损坏/非法/版本过高一律关闭）：
  协调器在调度引擎加载任务前解析，初始加载的防抖同步在「同步关闭」时绝不创建外部任务。
- **关闭路径次序**：先关门 → 经信号量排空在途同步 → 清理外部任务 → 持久化关闭 → 状态；
  `RefreshAsync` 保持协调器门与存储一致。开启路径：先持久化 → 开门 → 立即同步。
- 新增 3 项协调器测试（手动同步跳过不触外部不触发事件 / 防抖跳过不再重建 / 重开恢复）。

## 关键安全不变量核对

- **本地任务永远是事实源，绝不 inbound/双向**：同步只读本地 `GetAll()` 并只写外部；外部改动只被
  观察（`QueryOwnedAsync`）永不反向覆盖本地；外部触发只经时间闸门 + handler 回本地唯一调度/
  Workflow，绝不写本地事实源（源码契约断言 Core 同步层无 `SaveAsync`/`WriteAsync`）。
- **外部任务只回调本地应用，绝不携带电源命令**：外部动作恒为
  `ExecAction(AppExePath, "--trigger-task <id>", null)`；App 主/副实例收到触发只把稳定本地 id
  交给 `ExternalTaskTriggerService` 裁决，绝不直接执行电源（源码契约断言适配器/管道无
  shutdown.exe/SetSuspendState/ExitWindowsEx/IPowerService）。
- **清理只匹配三重条件（专属目录 + 应用标识 + 稳定本地 id）**：`TaskSyncNaming` 构建/解析回验；
  适配器查询/删除前防御性二次校验，非自家名一律 `Invalid` 拒绝；关闭同步 = 清理全部自家外部任务
  （同步门保证清理后任何本地变更都不会再把外部任务带回来）。
- **同步关闭 = 外部无本应用任务，绝不残留（D1）**：`TaskSyncCoordinator.Enabled` 门 + 关闭路径
  排空→清理→持久化；配置缺失/损坏/非法/版本过高一律保持关闭且 UI 如实上报，绝不静默启用。
- **配置读取区分 NotFound/Corrupt/Invalid/UnsupportedVersion，写入原子 + 备份证据**：
  `TaskSyncSettingsStore` / `TasksDocumentStore` 复用 `IStorage`（临时文件 + 替换 + backups/）；
  损坏数据绝不回退为可能触发任务的默认值。
- **唯一电源出口不变**：`ShutdownWorkflow` 仍是唯一允许调用 `IPowerService` 的模块；外部触发
  只构造 Executing 实例经 `IScheduledTaskHandler` 派发（WakeOnLan→执行器，其余→ShutdownWorkflow），
  双闸门与 Pre-Pipeline（OfficeSave→RunCommands→CloseApps→RtcWake）顺序原样生效；时间闸门拒绝/
  本地任务缺失/禁用/配置损坏 → fail-closed 不执行电源（`S22_ExternalTriggerTests` 覆盖）。
