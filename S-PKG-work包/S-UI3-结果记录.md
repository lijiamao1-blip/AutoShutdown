## 已实现内容

1. 根目录提供 `启动AutoShutdown安全测试界面.cmd`，该文件只调用受控 PowerShell 启动脚本。
2. `tools/Start-AutoShutdownUiTest.ps1` 获取真实工作区和 Git HEAD，执行当前源码 Release 构建；构建失败时返回非零退出码且不启动旧 EXE。
3. 使用 `%LOCALAPPDATA%\AutoShutdown\UiTestSandbox` 作为独立持久化测试数据目录，并通过 `AUTOSHUTDOWN_DATA_ROOT` 注入应用。
4. 启动前及应用启动时双重校验安全配置；配置损坏、`TestMode=false` 或发现危险开关时拒绝启动。
5. 默认关闭真实电源、无人值守、远程监听、Task Scheduler 同步、RunCommands、CloseApps 强杀授权及目标；不导入证书、PIN、HMAC secret 或配对数据。
6. 已有 AutoShutdown 实例时拒绝启动，不结束进程，不调用 `taskkill`，不向正式实例转发测试请求。
7. 安全测试窗口顶部显示“安全测试模式——不会执行真实系统电源操作”。
8. 日志与诊断页增加只读“当前测试环境”卡片，可查看模式、数据目录、构建提交、产品版本、真实电源权限、任务数量及日志目录，并提供打开目录、复制摘要和截图按钮。
9. 提供 `如何测试AutoShutdown界面.txt`。
10. 提供启动器契约测试和 UIA 冒烟脚本；UIA 脚本只使用窗口正常关闭机制，不强制结束进程。

## 使用结论与边界

当前实现可以使用。双击根目录 `启动AutoShutdown安全测试界面.cmd`，等待 Release 构建完成，并确认顶部出现安全测试模式提示后再进行界面操作。

若已有正式实例或测试实例，启动器会拒绝启动；用户需要先从托盘正常退出已有实例。测试任务不会执行真实系统电源操作，测试数据默认保留在独立沙箱中，程序不会自动上传数据。
