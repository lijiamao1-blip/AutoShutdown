## S17 独立验收缺陷修复（后续追加，未进入 S18）

独立验收发现两个高严重度 Office 真机缺陷。D1 已修复并独立提交；D2 命中架构阻断，暂停待裁决。

### D1 已修复：错误创建新 Office 实例（提交 `2d816c4`）

- **问题**：原 `ComOfficeAutomation.SaveOnStaThread` 用 `Activator.CreateInstance(type)` 创建 COM 实例，非附加运行实例；且代码禁止 Quit，可能遗留隐藏 Office 进程。
- **修复**：引入 `IOfficeComGateway` 网关收敛全部 Office COM 互操作；`TryAttach` 经 `Interaction.GetObject(string.Empty, progId)`（空路径 + ProgID = 纯 ROT 附加）只附加 Running Object Table 中已运行实例，移除 `Activator.CreateInstance`；无活动对象/附加失败返回 `NotDetected`，绝不创建、绝不 Quit，仅在释放本程序取得的 COM 引用。
- **结构契约**：`IOfficeComGateway` 只暴露 `TryAttach`（无创建入口）；`IOfficeComApplication`/`IOfficeComDocument` 无 Quit、无另存为入口。测试注入替身网关，全程不触碰真实 Office。
- **冻结不变量遵守**：ROT 附加用托管 `Interaction.GetObject`，不引入任何 P/Invoke / `Process.Start`，满足「原生导入仅存在于电源网关」源契约（8 处源码契约测试全过）。
- **证据**：新增 `S17_OfficeComGatewayTests` 8 项（结构契约 + 附加即保存 / 无活动不创建 / 枚举失败释放 / 无路径计数 / 保存异常 PartialFailure / 取消传播全释放）；Debug/Release 全量 721 通过（原 713 + 8）；Release 构建 0 警告 0 错误。

### D2 已修复：真正逐应用硬超时（GATE-S17-Q1 方案 A，提交 `1454ad3`）

- **问题**：`OfficeDocumentSaver.SaveApplicationAsync` 的 `Task.Run + CancelAfter` 只能协作取消；原 `ComOfficeAutomation` 内 `StaThreadRunner.Run` 用 `thread.Join()` 阻塞等待，一旦同步 COM 调用卡死，关机主流程被永久挂起。
- **红证据（先红后绿之「红」）**：一次性回归测试 `NonResponsiveAutomation_ExceedsDeadline_DoesNotReturn`（运行后已删除，不提交）证明：逐应用期限 100ms 下，注入「忽略取消、永不返回」的替身自动化后，`SaveAllAsync` 在 1500ms（15× 期限）仍未返回。

- **修复要点**：
  1. 新增 `AutoShutdown.OfficeSaveHelper`（net8.0-windows 控制台，唯一职责：ROT 附加已运行 Office→逐文档保存→输出固定最小结果→立即退出；内置 60s 最大生存期看门狗，父进程异常退出亦自终止不遗留）。ROT 附加仍走托管 `Interaction.GetObject`（无 P/Invoke），绝不 new Application / 创建实例 / Quit。
  2. 主程序经唯一网关 `IOfficeSaveHelperLauncher` / `OfficeSaveHelperLauncher` 启动辅助进程；`Process.Start` 全 App 仅存在于 `OfficeSaveHelperLauncher.cs` 一处。路径由 `AppContext.BaseDirectory` 固定解析，启动前校验文件存在且位于安装目录；`UseShellExecute=false`（不经 shell）；参数仅含受控枚举名与 GUID 标识（`ArgumentList` 直接传参，无引号注入）。
  3. `ComOfficeAutomation` 逐应用：启动辅助进程→轮询 `WaitForExit` 并响应取消→超时/取消时 `Kill(entireProcessTree:true)` 终止整棵进程树、等待确认退出后才传播取消→解析 stdout 固定结果（缺失/非法回退 TimedOut）。绝不 `Task.WhenAny` 后丢弃仍在运行的辅助进程、绝不终止用户 WINWORD/EXCEL/POWERPNT。
  4. 源契约收紧：更新 7 处源码契约测试，「`Process.Start` 仅允许存在于 `OfficeSaveHelperLauncher.cs`」；新增结构契约测试（辅助进程无 `DllImport` / `Activator.CreateInstance` / `Process.Start` / Quit）。

### D3 已修复：取消清理覆盖 OCE / 确认退出被忽略 / 解析前取消竞态（提交 `75d35b7`）

- **问题**：`ComOfficeAutomation.SaveOpenDocuments` 在取消/硬超时时调用 `KillTree()` 后忽略 `WaitForExitAfterKill` 的布尔结果；若终止或确认退出异常，可能覆盖原始 `OperationCanceledException`，进而被 `OfficeDocumentSaver` 当作一般异常转换为 `NotDetected`；另外 Helper 已退出后、解析 stdout 前存在取消竞态，可能返回掩盖取消的正常结果。
- **修复要点**：
  1. 将「取消/超时后的 Helper 清理」收敛为可测试私有逻辑 `CleanupAfterCancellation`（仅针对已启动的 Helper，终止整棵进程树 + 有界等待确认退出）；`App.csproj` 加 `InternalsVisibleTo` 供聚焦回归测试直接验证。
  2. 不得忽略「确认退出」结果：`WaitForExitAfterKill` 返回 false（含 Kill/等待确认抛异常）时抛出 `HelperCleanupFailedException` 作为明确失败路径，绝不静默忽略、绝不伪装成功/正常结果。
  3. 取消处理边界 `try { CleanupAfterCancellation } catch (Exception) { }` 再 `throw;`：无论清理发生何种异常，外部取消都仍以 `OperationCanceledException` 传播，绝不被转换为 `NotDetected` 或其他普通结果。
  4. 在 `WaitForExit(...)` 返回 true 后、读取 stdout 前再次检查取消令牌，消除取消竞态：取消已到达则走取消清理路径。
  5. 保持：不终止 WINWORD/EXCEL/POWERPNT；不使用 `Task.WhenAny` 丢弃后台工作；不使用 `Thread.Abort`；不新增任何 `Process.Start`；Helper 仍绝不创建 Office、绝不 Quit。
- **聚焦回归测试（新增 5 项，另强化正常超时路径断言确认退出计数）**：`Cleanup_UnconfirmedExit_ThrowsHelperCleanupFailed_NotSilentlyIgnored`（WaitForExitAfterKill=false 不被静默忽略）；`Cancel_KillTreeThrows_StillPropagatesOce`；`Cancel_ConfirmExitThrows_StillPropagatesOce`（Kill/确认退出抛异常时外部取消仍传播 OCE）；`HelperExited_ThenCancelled_BeforeParse_StillPropagatesOce`（Helper 已退出但在解析前取消仍传播 OCE，并执行清理）；`Cleanup_NullProcess_IsNoOp`。
- **测试与构建**：S17 相关测试 40 通过（helper/worker）；Debug 全量 753 通过 / 0 失败 / 0 跳过；Release 全量 753 通过 / 0 失败 / 0 跳过；Release 构建 0 警告 0 错误。

### D4 已修复：取消清理失败不再被空 catch 丢弃，形成 fail-closed 安全故障（提交 `0c188bd`）

- **问题**：独立复验发现 D3 的生产路径仍吞掉清理失败——`SaveOpenDocuments` 在 `catch (OperationCanceledException)` 中调用 `CleanupAfterCancellation(process)` 后用 `catch (Exception) { }` 丢弃 `HelperCleanupFailedException`。因此 `WaitForExitAfterKill=false`、Kill 失败或确认退出异常，在真实硬超时路径可能退化为 TimedOut 并继续默认 Continue；「确认退出失败不得静默忽略」未成立。
- **修复要点**：
  1. 新增可识别安全故障 `OfficeHelperCleanupFailedException`（Core，派生自 `OperationCanceledException`）：清理失败不再被空 catch 丢弃，`SaveOpenDocuments` 在清理失败时抛出该异常（OCE 子类，外部取消仍以 OCE 语义传播）。
  2. `OfficeDocumentSaver.SaveApplicationAsync` 区分外部取消与内部硬超时：外部取消期间的清理失败仍以纯 OCE 传播（绝不转 NotDetected）；内部硬超时期间的清理失败向上传播为安全故障（绝不降级为 TimedOut/NotDetected）。
  3. `OfficeSaveAction` 增加最小 fail-closed 分支：仅当捕获 `OfficeHelperCleanupFailedException` 时，将本次运行的失败策略从默认 Continue 覆盖为 Block（普通 Office 保存失败仍 Continue；Runner 通用 block/continue 语义未改）。
  4. 保持：不新增任何 `Process.Start`；不终止 WINWORD/EXCEL/POWERPNT；不使用 `Task.WhenAny`/`Thread.Abort`；Helper 仍绝不创建 Office、绝不 Quit。
- **聚焦回归测试（新增 4 项 Theory = 12 用例；另将 2 项 D3 断言由 `Assert.Throws` 升级为 `Assert.ThrowsAny` 以接受 OCE 子类）**：
  - `HardTimeout_CleanupFailure_ThrowsOfficeHelperCleanupFailed`（SaveOpenDocuments 层：未确认退出 / Kill 异常 / 确认退出异常 → 抛安全故障，不被空 catch 丢弃）；
  - `SaveAll_InternalTimeoutCleanupFailure_PropagatesNotConverted`（OfficeDocumentSaver 层：内部硬超时清理失败传播安全故障，不转 TimedOut/NotDetected）；
  - `SaveAll_ExternalCancelCleanupFailure_PropagatesOce`（OfficeDocumentSaver 层：外部取消清理失败仍 OCE，不转 NotDetected）；
  - `EndToEnd_CleanupFailure_BlocksPipeline_AndNeverAllowsPower`（端到端 SaveOpenDocuments→OfficeDocumentSaver→OfficeSaveAction→PrePipelineRunner：三种失败均 Block、`PowerAllowed=false`、唯一电源出口不触发）。
