## 1. tasks.json schema 与版本字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `SchemaVersion` | `int` | 当前 = 1；必须存在且为整数；>1 判 UnsupportedVersion；<1 无迁移链判 Invalid |
| `Tasks` | `TaskDefinition[]` | 任务清单；可为空数组但不得为 null |

- **与 config.json 分离**：文件名 `tasks.json`，独立于 `config.json`；二者各自 `SchemaVersion`。
- **V2 新增文件**：V1 无 tasks.json，故**无 V1→V2 迁移链**（架构书 §4.1/§4.2 只对 runtime.json/config.json 定义迁移；tasks.json 是全新文件）。
- 每个 `TaskDefinition` 直接序列化（Id/Kind/Action/CountdownDuration/TargetTimeOfDay/WarningSeconds/CreatedAt/RealPowerConfirmed/IsEnabled/Priority），复用 T02A 冻结字段，不新增字段。

## 3. NotFound 与 Corrupt 的处理方式

| 存储读取状态 | 映射结果 | 行为 |
|-------------|---------|------|
| `NotFound`（文件不存在） | `TasksLoadStatus.NotFound` | `Document = null`；调用方自行决定「无任务」语义，**不伪造空文档** |
| `Corrupt`（文件存在但 JSON 损坏） | `TasksLoadStatus.Corrupt` | `Document = null`；**绝不回退为空任务集或危险默认任务** |
| `IoFailure` | `TasksLoadStatus.IoFailure` | 上抛 I/O 错误 |
| 根非对象 / SchemaVersion 缺失或非整数 | `TasksLoadStatus.Invalid` | 拒绝 |
| `SchemaVersion > 1` | `TasksLoadStatus.UnsupportedVersion` | 拒绝（未来版本数据） |
| `SchemaVersion < 1` | `TasksLoadStatus.Invalid` | 拒绝（无迁移链） |
| 任务结构无效（如 Countdown 缺时长） | `TasksLoadStatus.Invalid` | 拒绝，**不静默丢弃/回退** |

写入时同样逐任务结构校验 + 版本校验，无效则 `TasksSaveStatus.Invalid` 且**不落盘**。

## 5. 关于 IConfigurationService 的默认接口方法（重要说明）

`IConfigurationService` 是全局配置接口，仓库中有 12 个既有测试替身（10 个测试文件内）实现它。若在接口新增**抽象**方法，将破坏这些替身的编译，其中多个文件归属后续卡（`SchedulerEngineTests.cs` 归 T04、`ShutdownWorkflowTests.cs` 归 T07）。

为避免越界修改其他卡的测试文件，`LoadTasksAsync`/`SaveTasksAsync` 以**默认接口方法（fail-fast `throw NotSupportedException`）**提供，生产 `ConfigurationService` 显式覆写。这样：
- 既有测试替身**无需改动**即可编译；
- 生产实现不被影响；
- 未来任何未覆写该方法的实现都会立刻抛错，而非静默返回默认值。
