AutoShutdown UI 预览启动器说明（开发环境专用）
=================================================

一、两个入口的区别

1. 「启动UI预览.cmd」
   - 先切换到项目根目录，不依赖当前终端位置；
   - 检查指定 .NET SDK，缺失时回退到系统 PATH 中的 dotnet，
     两者都不可用时显示中文错误并停止；
   - 使用 Release 配置重新构建 AutoShutdown.sln；
   - 构建成功后才启动 src\AutoShutdown.App 的 Release EXE；
   - 构建失败会显示“构建失败，未启动软件”，保留错误输出，
     不启动旧的 EXE，等待按键后退出。

2. 「仅打开现有UI.cmd」
   - 不执行任何构建；
   - 直接打开最近一次成功构建的 Release EXE；
   - 若 EXE 不存在，提示：
     “尚未找到可运行的 UI，请先运行“启动UI预览.cmd”完成构建。”

二、实现说明

- 两个 .cmd 是纯文本入口，实际逻辑与中文提示位于
  tools\Start-UiPreview.ps1；
- 请保持 tools 目录下的四个文件（两个 .cmd、Start-UiPreview.ps1、
  本说明）在同一目录，不要单独移动。

三、常见问题

- 如果构建提示文件被占用（例如编译报错无法写入
  AutoShutdown.App.exe），请先从系统托盘菜单正常退出旧实例，
  再重新运行「启动UI预览.cmd」。

四、安全说明

- 这些脚本只属于开发环境，不进入正式发布包；
- 脚本不修改任何 C#/XAML/项目文件，不写注册表，不设置开机自启，
  不结束任何正在运行的进程，不使用管理员权限；
- 脚本不会删除 bin/obj，也不会运行测试；
- 当前软件仍为安全测试模式（FakePowerService），
  不会执行真实关机、重启、睡眠或休眠操作；
- 启动时遵守现有单实例与 Named Pipe 机制：若软件已有实例，
  只会唤起已有窗口，不会强制启动第二个后台实例。
